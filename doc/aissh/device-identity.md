# 固定设备身份与自动凭证

## 日常使用

`aisshc` 首次启动保存随机 `dev-` ID 和 Ed25519 私钥到状态目录的 `identity.json`。用户无需输入密钥、token 或注册密码。已有安装升级会自动迁移旧 ID；之后切换 Wi-Fi、有线或雷雳接口、随机 MAC、重启及程序升级均不重新生成设备身份。SSH 登录仍使用目标系统账户的认证方式。

设备凭证与设备 ID、授权、本地端口分别管理。私钥仅保存在客户端，Unix 文件权限为 0600、目录为 0700；Windows 服务状态目录继承 SYSTEM/管理员访问控制。服务器保存公开验证密钥与辅助硬件哈希，不保存客户端私钥。配置、日志、公开发行包和容器镜像不包含设备凭证。

## 登录与内网

客户端向节点请求有效期一分钟的随机挑战，用设备私钥对设备 ID、挑战、公开密钥、硬件观察和账户资料签名。节点校验公钥绑定及一次性挑战后签发既有 24 小时会话。挑战使用一次后失效；服务端重启后旧挑战失效。公网与内网分别签发挑战、认证会话。

香港把设备公钥纳入现有签名权限快照；内网节点无需持有设备私钥，外网中断时可验证已登记设备，仍受最后签发权限的 24 小时期限限制。首次登记和旧设备首次绑定必须联系香港，不能在内网节点独立绑定。

## 旧设备迁移

先升级香港和内网服务端，再逐台升级客户端。未迁移的旧客户端继续使用旧协议；一台设备完成绑定后，两台节点均拒绝它的无凭证登录（内网在下一次权限同步后生效，正常每 10 秒）。绑定时使香港的旧会话失效；内网同步新凭证时也会回收其无凭证会话。

首次升级会一次性提交当前网卡及可用网卡的旧指纹候选。服务器寻找原记录，保留其 ID、管理员角色、授权方向、端口、创建时间和 STCP 密钥，只新增设备公钥和硬件辅助信息。如果原网卡已经消失，服务器可以用记录中的旧 MAC 与当前硬件哈希重算旧 ID；只有结果唯一时才自动认领。不会按主机名或用户名合并设备。存在多条可见网卡对应的历史记录时，沿用最近活动的原记录，不自动合并其他记录或授权。

身份先保存到本地，再请求绑定；服务端响应丢失时，凭相同私钥重试不会创建设备副本。身份文件无法写入、损坏、权限错误或疑似被复制时，明确报错，不静默生成新身份。若找不到可验证的历史记录，不凭相同机器名迁移权限。

旧协议没有设备凭证，因此首次绑定继承旧硬件注册协议的信任边界；硬件指纹不能提供持有证明。绑定完成后不会再允许凭硬件信息替换公钥。需要逐台完成升级，才能消除未迁移设备的旧协议风险。

## 手动运行与开机启动

默认手动执行只检查或恢复已安装服务，不运行副本。`--foreground` 默认读取固定安装配置中的同一状态目录；文件锁保证同一目录只由一个运行中的客户端持有。Unix sudo 前台运行会采用配置中的服务用户，避免 root 创建不可读身份。Windows 前台身份转为计划任务时，安装流程保留同一份身份。

`--state-dir` 显式指定一个独立安装目录；同一硬件上缺失已绑定凭证的新目录不能认领原设备。如果需要并行独立设备身份，应使用独立机器，不复制身份文件。

## 硬件变更、丢失与回滚

硬件哈希只作辅助校验：MAC 变化不拒绝登录；机器硬件标识均明显不同且没有共同标识时，客户端停止并提示疑似克隆。临时无法读取硬件信息时沿用已有凭证，不能因为信息缺失重新生成 ID。它不是硬件远程证明：复制凭证且同时伪造相同硬件信息仍不能靠软件指纹区分，因此不要把身份文件放进虚拟机模板、镜像或公开备份。

身份文件丢失时优先恢复该文件的私密备份；不要删除文件尝试修复网络问题。已绑定的设备不能仅凭 MAC 重新获取原授权。确认无法恢复时，由管理员删除旧设备并清理客户端身份后，作为新设备重新登记和授权。

部署前备份服务器设备数据库、旧二进制和客户端状态目录。已经绑定的设备不能直接回退到无凭证客户端；回滚必须恢复对应数据库备份及客户端状态，避免授权或凭证绑定不一致。原有会话、权限撤销、禁用、删除和内网租期机制继续生效。
